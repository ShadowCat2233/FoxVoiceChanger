# FoxVoice 方案执行纠偏审计

审计日期：2026-09-10  
基准：已发布交互原型、`app/page.tsx`、`docs/FOXVOICE_ARCHITECTURE.md` v0.3

## 为什么此前的执行是错的

1. 把 Rust 音频、模型库和进程骨架“能够编译”误写成产品“已完成”。
2. 没有把交互原型作为桌面端的强制设计基准，擅自用三个普通 WPF 页签替换了五模块工作台。
3. 只验证了进程存活和命令行输出，没有验证用户实际点击导航、设备弹窗、启动按钮和实时参数。
4. 没有在纯单文件、无同目录伴随程序的环境中验证启动，导致发布方式与启动假设不一致。
5. 没有合法的 Generator、ContentVec、RMVPE 权重和虚拟声卡时，仍把“完整 RVC 可用”写入验收结论。

## 本次已纠正

| 原型/方案要求 | 当前实现 | 验证方式 |
| --- | --- | --- |
| 左侧五模块工作台 | 实时变声、模型库、音效板、模型训练、组件中心全部恢复；设置与诊断保留在底部 | Windows UI Automation 逐项切换并读取页面标题 |
| 实时声场与声音预设 | 恢复中央声场、设备路由、模型选择、开始/停止和动态预设区 | 真实设备与本地模型库驱动，不使用原型假数据 |
| 游戏保护与快速调音 | 独立引擎高优先级、实际处理预算、音高、输出增益、噪声门 | UI 控件调用引擎标准输入实时参数协议 |
| 功能失败不闪退 | 后端延迟发现、UI 级异常拦截、可读错误和本地崩溃日志 | 开发构建、发布构建和纯单文件隔离启动 |
| 自包含发布 | 原生 supervisor/engine 内嵌到 `FoxVoice.exe`，仍保留伴随文件以减少首次提取 | 删除伴随文件的隔离目录启动并验证自动提取 |
| 发布不被旧文件污染 | 先发布到临时目录，完成哈希和压缩后再原子替换成品 | `build-release.ps1` 和 `smoke-release.ps1` |

## 后续完成门槛

任何模块只有同时满足以下条件才能进入“已完成”：

1. 原型中的入口、状态、空态和错误态存在；
2. 控件连接真实实现，不是硬编码演示数据；
3. 开发构建和发布包都通过真实点击或协议级测试；
4. 所需外部驱动/权重缺失时给出可执行引导，不闪退、不假装可用；
5. 文档明确记录尚未覆盖的硬件和压力测试边界。
