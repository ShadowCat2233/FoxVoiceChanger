# FoxVoice 实施状态

更新时间：2026-09-11
状态口径：只记录已经接入真实实现并完成相应验证的能力。完整差异见 `IMPLEMENTATION_AUDIT.md`。

## 当前可用

- 与交互原型一致的 Windows 五模块工作台布局；
- 真实 WASAPI 麦克风/输出设备枚举、选择和持久化；
- 安全旁路的启动、停止、采样率与欠载指标显示；
- 独立 WindowsML/DirectML RVC 引擎进程；
- 运行中实时调整音高、输出增益和轻量噪声门；
- 本地 `.onnx`、`.pth`、`.index` 导入、SHA-256 去重、结构门禁、状态展示和可恢复的回收区移除；
- Hugging Face 单文件或仓库/分支浏览、仓库许可证/私有/受限状态展示、候选文件选择、用户取消/游戏暂停、Range 断点续传、代理探测与导入；
- 启用 F0 的 RVC v2 `.pth` 可通过独立纯 Rust sidecar 转换为流式 ONNX，并重新经过结构门禁和哈希导入；
- ContentVec、RMVPE 和 Generator 路径进入固定版本 `vc-app`/`vc-core` 推理链；
- 设置页的三模型自检不打开音频设备，直接在 WindowsML/DirectML 上建立 RVC 管线并执行一帧非静音推理，输出加载/推理耗时；
- 硬件诊断、后端推荐与虚拟音频设备检测；
- 引擎异常后的安全旁路恢复；
- 游戏保护已接入真实遥测闭环：处理耗时、输出欠载、输入溢出和输出丢样均读取自 RVC 引擎；连续超载先进入不重载模型的观察稳定档，再以原子开关切入保生存原声旁路，持续恢复后无重载返回 RVC；已移除会关闭音频会话并重新加载三模型的动态块长切换；
- 游戏进程感知已接入：前台窗口连续覆盖显示器 90% 以上时识别独占全屏/无边框应用，主动保持稳定档，并暂停新发起的下载、转换和模型自检；退出画面后经迟滞解除；
- 设备热插拔已接入：空闲轮询刷新，运行中端点失效会重新枚举并降到默认设备安全旁路；
- 音效板已接入 WAV/FLAC/MP3/OGG 文件管理、向后兼容持久化、四组筛选、单项循环/再次触发停止、增益、下混/线性重采样、5 ms 首尾淡化、独立限幅、当前主输出共享混音、隔离播放进程和 8 个系统级热键；
- 单轨离线编辑已接入：支持 WAV/FLAC/MP3/OGG 输入、波形摘要、毫秒级双滑块裁剪、所选原声试听；使用当前 Generator、ContentVec、RMVPE 与音高执行独立 RVC 转换，结果以临时文件提交为 WAV 或纯 Rust 编码的 FLAC，并可立即试听；游戏或实时引擎运行时拒绝启动；
- 模型详情已接入：名称、作者、许可证和标签可在桌面端编辑；Hugging Face 导入会尽力带入仓库作者与许可证；最小只读 ONNX protobuf 解析器从输入通道、标准 F0 输入与 metadata_props 提取 RVC v1/v2、F0、采样率和 streaming 标记；选择模型和真实 RVC 自检分别记录最近使用时间、通过/失败状态与执行后端；新增字段均有 serde 默认值，旧版 `model.json` 无需迁移即可读取并自动补扫；无法可靠识别的说话人数量仍保持未知，不做猜测；
- 训练组件管理已接入：固定官方 RVC commit，按需自动安装 Python 3.12、FFmpeg、隔离 venv、CPU/CUDA PyTorch、依赖和训练权重；状态逐项自检，支持取消，游戏检测会停止后台安装并保留可复用缓存；
- 训练任务入口已接入：除托管官方本机训练工作台外，FoxVoice 原生表单可选择授权数据集、实验名、轮数和批大小，一键执行固定 RVC v2 40 kHz F0/RMVPE 的预处理、特征提取、训练及索引生成；支持取消/游戏停止，成功后自动经过现有模型门禁导入 `.pth/.index`；
- Windows ML 发布依赖已修复：固定并校验 Windows App SDK Foundation NuGet，随 ZIP 和单文件内嵌 bootstrapper 及许可证；组件中心可读取系统 EP 目录，并以当前三模型执行真实 TensorRT RTX 安装/自检后才设为首选后端；
- 单文件自包含启动、原生组件按哈希提取和崩溃日志；
- 分阶段发布、SHA-256 清单、便携 ZIP 和自动冒烟测试。
- 当前用户单文件安装器已接入：内嵌便携发布负载，解压前阻止路径穿越，安装前逐文件流式校验 SHA-256；使用隔离 staging 和同卷目录切换完成安装/修复/升级，保留上一版并支持双向回滚；注册当前用户卸载入口和快捷方式，卸载明确保留模型、组件、设置与训练数据；
- 真实 RVC 长稳测试器已接入：自动解析当前 Generator 与已校验 ContentVec/RMVPE，按当前音频路由运行，逐秒采集 P99、块预算比例、输入溢出、输出欠载和丢样，区分稳态与切档窗口并生成 JSON 报告；可定时循环稳定/生存/恢复档验证无重载切换；
- 中英文界面已接入：设置页可即时切换简体中文与 English，选择持久化到当前用户设置；导航、实时工作台、模型库、音效板、训练、组件、设备、诊断和主要运行状态共用同一翻译层，切换不会重启实时音频进程或重建模型链路；
- 双输出长稳测试器已接入：自动解析 VB-CABLE 成对的渲染/采集端点、当前物理监听设备和三模型配置，同时启动高优先级 RVC 主链路与低优先级监听链路，分别检查 Running、欠载、输入溢出和丢样并输出 JSON 报告；

## 本机验证结果

- Windows x64，NVIDIA GeForce RTX 4060 Ti；
- 8 个 WASAPI 输入/输出端点可枚举；
- DirectML 为当前推荐后端；
- 安全旁路达到 `Running`，48 kHz，实时参数命令发送后进程继续运行；
- Windows UI Automation 已点击验证五个导航、设备弹窗、无模型启动引导、旁路启停和音高调整；
- 发布目录与纯单文件隔离启动都保持响应，内嵌的三个原生组件及 Windows ML bootstrapper 能够自动提取；
- Rust 工作区 38 个测试通过，Clippy 使用 `-D warnings` 通过；
- 当前本机模型库有 1 个可用 ONNX Generator 和其来源 `.pth`；DirectML 三模型 100 帧真实基准平均 28.2 ms、P95 30.7 ms、P99/最大 35.2 ms，非静音输出成功；Generator 来源许可证仍需用户自行确认。
- 组件中心已接入 ContentVec/RMVPE 的按需安装、GPL-3.0 确认、临时下载、长度/SHA-256 强校验与自动路径配置；基础权重仍不随发布包分发。
- VB-CABLE 已被枚举；“麦克风 -> RVC -> CABLE Input”短时真实链路运行 12 秒，稳态处理 34–41 ms。到具体游戏的设备选择、听感和本地监听仍待人工验收。
- 修复前的保护档重配置短测测得 672.958 ms 峰值与 197 次欠载；移除会话重载后，18 秒标准/稳定/生存档循环保持 `Running`，P99 55.137 ms、最大块预算占比 34.46%、稳态欠载 0，RVC/原声切换窗口欠载 11，计数器未重置。此结果只证明短时回归，不替代 4 小时游戏压力验收。
- 安装器在临时隔离根目录完成真实负载校验、安装、修复、上一版保留、回滚和卸载全流程；测试模式不写真实快捷方式、卸载注册表或用户安装目录。
- 当前真实 Generator 的结构补扫得到 RVC v2、F0、48 kHz 与 streaming，来源为模型 protobuf 输入/metadata_props；历史 URL 编码中文显示名已安全解码。
